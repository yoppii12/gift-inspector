# デモキット（デモ用オーダーと撮影用の印刷物）

元データ: `db/seeds/demo_orders.json`（唯一の元データ。SQL シード・QR・印刷物はここから生成する）
生成: `npm run demo-kit` → `db/seeds/001_demo_orders.sql`、`tools/demo-kit/out/qr/*.png`、`tools/demo-kit/out/<yymmdd>_デモ用QRコード一覧.pdf`、`tools/demo-kit/out/<yymmdd>_擬似のし・カード.pdf`

## デモ用オーダー

「登録」は DB に入る正解、「現物」は撮影用に印刷する内容です。人名・文面はすべて架空です。

| オーダー | 表書き | 宛名 | カード | 水引 | 想定 | 現物との違い |
|---|---|---|---|---|---|---|
| GIFT-DEMO-001 | 御祝 | 佐藤 花子 | あり | 蝶結び | **OK** | なし（のし＋カード） |
| GIFT-DEMO-002 | 内祝 | 高橋 健一 | なし | 蝶結び | **OK** | なし（のしのみ） |
| GIFT-DEMO-003 | 御礼 | 鈴木 一郎 | あり | 蝶結び | **NG（表書き）** | のしの表書きを「御祝」で印刷 |
| GIFT-DEMO-004 | 快気祝 | 渡辺 直樹 | なし | 結び切り | **NG（宛名）** | 宛名を「渡部 直樹」で印刷（1文字違い） |
| GIFT-DEMO-005 | 寿 | 山本 恵 | あり | 結び切り | **NG（カード）** | カードを「末永いご多幸を」で印刷 |

- NG ケースは、主判定の3項目（表書き・宛名・カード）をそれぞれ1件ずつ含みます（テストで保証）。
- 004 は「似ているが違う名前を OK にしない」ことを見せるためのケースです。
- 元データに矛盾（「想定OKなのに現物が登録と違う」など）があると、生成とテストが失敗します。

## 印刷物

- QR コード一覧（A4）: 生成済み。オーダー確認画面で読み取って使う。
- 擬似のし・メッセージカード: `tools/demo-kit/out/<yymmdd>_擬似のし・カード.pdf`（A4 縦、1オーダー1ページ。実物サンプルの受領までの代替）
  - のしは毛筆体（Yuji Syuku）、カードは明朝体（Shippori Mincho）。どちらも OFL-1.1
  - 印刷するのは「現物」（`printed`）の内容。意図的 NG のオーダーは登録と違う文字で印刷される
  - **印刷物には登録内容・想定結果を載せない**（写真に写り込むと AI に正解の手がかりを与えるため）。載るのは現物の内容のほかは、オーダー番号・切り取り線・「擬似のし・カード（社内検証用）」「点線で切り取って撮影」などの案内だけ
  - のし・カードを描くかどうかも現物（`printed`）で決める。現物ののしは表書き・宛名・水引を全部入れるか全部空にし、カード文面は 120 文字までにする（`npm run demo-kit` とテストで検証）

### 印刷と撮影のしかた
1. A4 に**拡大・縮小なし（100%）**でカラー印刷する
2. 点線で切り取る（のし 100×240mm、カード 80×120mm）。オーダー番号の小さな文字は切り落としてよい
3. 作業台に、のしとカードを重ならないように並べ、真上から撮影する

10/7 の確認: 印刷用 PDF の画像を Claude（claude-opus-5-5、effort=low）で各2回読ませ、**10/10 回とも意図どおりの判定**（001・002 = OK、003 = 表書き NG、004 = 宛名 NG、005 = カード NG、水引も正しく読取）。実際に印刷・撮影した場合の結果は社内検証で記録する。

## 判定不能・エラーを見せたいとき

デモで「判定不能」「エラー」の表示も見せる場合は、次の方法を使います（10/15 の障害注入訓練で手順を確定）。

- 判定不能: のし・カードを写さずに撮影する、またはピントを外して撮影する
- エラー: 社内検証環境で `AI_PROVIDER=mock`、`AI_MOCK_SCENARIO=timeout` などに切り替える（**デモ環境では行わない**）
