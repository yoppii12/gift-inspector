# ギフト出荷 AI検品アプリ　デザイン仕様書

ギフト出荷の作業台で、のし・メッセージカード・カタログギフトを撮影し、WMSの登録内容とAIで照合するアプリ。
作業者はタブレット／スマートフォンのブラウザで使う。見た目の正解は `screens/` の3枚。

## 1. 前提

- 利用者：物流センターの検品作業者。作業台の前に立ったまま片手で操作する
- 端末：カメラ付きタブレット／スマートフォン（ブラウザ）。基準幅 390px、タブレットでは最大幅 480px で中央寄せ
- 運用：1日 150〜200件。判定OKなら出荷確定まで自動、NGのときだけ作業者が確認する
- 社名は画面に出さない。オーダーNo・氏名・件数はすべて架空

## 2. デザイントークン

### 色（この3色と、メインカラーの濃淡だけを使う）

| トークン | HEX | 用途 |
|---|---|---|
| base | #FFFFFF | 背景 |
| main | #171A31 | アプリバー、主要ボタン、本文、OKアイコン、検出枠 |
| accent | #F05A22 | NGだけに使う（NG枠・NGアイコン・アラートの左帯・確認済みの印）。画面面積の3%未満 |
| main-90 | #393C4F | 強めの補助テキスト |
| main-60 | #737583 | ラベル、補足テキスト |
| main-40 | #9D9EA8 | プレースホルダー、非アクティブ |
| main-25 | #CBCCD1 | 未到達ステップの枠 |
| main-15 | #E0E1E4 | カード枠線、区切り線（強） |
| main-08 | #EEEEF0 | 区切り線（弱）、OKチップ背景 |
| main-04 | #F6F6F7 | 情報カード・検索欄・アラートの背景 |

緑や赤の「成功／エラー色」は使わない。OKはメインカラーのチェック、NGはアクセントカラーの「！」で表す。

### タイポグラフィ

- 欧文・数字：Inter、和文：Noto Sans JP（`font-family: "Inter", "Noto Sans JP", sans-serif`）
- ウェイト：Regular 400 / Medium 500 / SemiBold 600

| 用途 | サイズ | ウェイト |
|---|---|---|
| アプリバータイトル | 18px | 600 |
| オーダーNo（強調） | 17px | 600 |
| セクション見出し | 15px | 600 |
| ボタン | 15px | 600 |
| アラート見出し | 14px | 600 |
| 本文・値 | 14px | 500 |
| リスト項目名 | 12.5px | 500 |
| ラベル・補足 | 11〜12px | 400 |
| 集計の数値 | 22px | 600 |

### 形と余白

- 画面左右の余白 16px、カード内余白 16px
- 角丸：カード・ボタン・検索欄 10〜12px、チップは高さの半分（ピル型）、検出枠 2px
- 主要ボタン：高さ 50px、塗り main、文字白。副ボタン：白地に main の 1.3px 枠
- 影は使わない。区切りは線（main-15 / main-08）で表す
- アイコン：MUI Icons（Outlined）。OK＝塗り円のチェック、NG＝塗り円の「！」

## 3. 画面構成

共通：上部にアプリバー（main 塗り、高さはステータスバー込みで約100px）、下部にタブ（検品／履歴）。判定画面（②）だけはタブを出さず、ボタン2つを固定表示する。
検品フローの画面上部には3段のステッパー（①読取 → ②撮影 → ③判定）を出す。完了ステップはチェック、現在は塗り円に番号、未到達は枠線のみ。

### ① オーダー確認（`screens/01_order_confirm.png`）

- 初期状態：「パッキングリストのコードを読み取ってください」＋カメラでのQR／バーコード読取。プロトタイプでは「デモ用オーダーを読み込む」ボタンで代替してよい
- 読取後：
  - 情報カード（main-04）：チェック＋「パッキングリストを読み取りました」、オーダーNo、出荷予定日
  - 「検品する内容」（右に小さく「WMS登録情報」）：商品（名称＋裏面バーコード）、のし（有無＋水引）、表書き、名入れ・宛名、メッセージカード（有無＋文面）
  - 補足「のし・カード・カタログを作業台に並べて撮影します」
  - 主要ボタン「撮影に進む」

### ② 撮影（モックアップなし。①②と同じトーンで作る）

- カメラのプレビューを全幅で表示し、作業台全体が入るよう枠のガイドを重ねる
- 下部に丸いシャッターボタン（main）。「撮影する」
- カメラが使えない環境・デモ時は `assets/sample_ok.png` / `sample_ng.png` を撮影画像として使う
- 撮影後は判定中の表示（「AIが照合しています」＋進捗）を短く出して③へ

### ③ AI判定結果（`screens/02_ai_result_ng.png`）

- 撮影画像の上に検出枠を重ねる。座標は `assets/detection_boxes.json`（画像サイズに対する0〜1の比率）
  - OK項目は main の枠＋ラベル、NG項目は accent の枠＋ラベル
  - ラベル：カタログ／水引／表書き／名入れ／カード
- NGがあるとき：アラート（main-04 地、左に accent の4px帯、NGアイコン）
  - 見出し例「表書きが登録内容と一致しません」、補足「現物を確認し、結果を記録してください」
  - ボタン：副「撮り直す」／主「確認して記録」
- すべてOKのとき：アラートの代わりに「すべて登録内容と一致しました」（main のチェック、accent は使わない）
  - ボタン：副「撮り直す」／主「出荷を確定」→ WMSへ送信 → トースト「出荷を確定しました」→ ①の初期状態へ
- 「判定内容」リスト（右に「OK 4件　要確認 1件」）：項目ごとにアイコン、項目名、結果
  - OK は結果を main-60 で、NG は「読取「御礼」 / 登録「御祝」」を main の太字で表示
- 「確認して記録」→ 確認ダイアログ（「現物を確認し、正しい状態にしましたか？」／「記録する」）→ 状態を「確認済み」として履歴に追加し、WMSへ送信

### ④ 検品履歴（`screens/03_history.png`）

- 検索欄「オーダーNoで検索」（入力で一覧を絞り込む）
- 「本日 MM/DD」＋右に「画像は最大半月保存」
- 集計カード：検品済み／OK／確認済み の件数（3分割）
- 一覧：サムネイル、オーダーNo、時刻＋表書き、「WMS送信済み」、右にチップ
  - OK：main-08 地のチップ「OK」
  - 確認済み：白地＋main 枠のチップ「確認済み」、その左に accent の小さな丸
- 行をタップすると詳細（撮影画像＋検出枠＋判定内容、記録した時刻）を表示

## 4. 文言のルール

- 作業者に分かる言葉で書く（「推論」「API」などの言葉は出さない）
- ボタンは動作をそのまま書き、結果の表示でも同じ言葉を使う（「出荷を確定」→「出荷を確定しました」）
- エラーは何が起きたかとどうすればよいかを書く（例「コードを読み取れませんでした。パッキングリストを枠の中に入れてください」）

## 5. 対象外

- 手書き文字の読み取り
- 実際のAIモデル・実際のWMSとの接続（プロトタイプではダミー）
